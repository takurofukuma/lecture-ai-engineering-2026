実行環境：Codespaces ではなくローカルの Mac（uv 0.13.2）。API キーは環境変数 `GEMINI_API_KEY` で渡した。モデルはすべて既定の `gemini-3.5-flash-lite`。

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：「おそらくAIに関する特定の講座」と前置きしたうえで、一般論として「レベル1：基本（チュートリアル通りに進める）」「レベル2：応用（自分の業務に合わせて工夫する）」「レベル3：発展（ゼロから課題を設定する）」と答えた。「具体的な定義は講座によって異なります」と断りも入れていた。
- 用語集の正しい意味と比べて気づいたこと：正しくは「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」で、**どれか1つで完了**、原則として採点しない。モデルは「発展」という語だけ当てたが、2段目の「実装」を「応用」と答えた。また、易しい順に段階を上がっていく構成として説明しており、「どれか1つ選べば完了」という肝心の点は出てこなかった。断りを入れつつも、中身はもっともらしい作り話だった。
- 表示できたトークン数（入力 / 出力）：「LoRAとは何ですか？」が **7 / 609**、宿題の3レベルの質問が **21 / 450**。短い質問でも出力側が長く、トークンのほとんどは回答で使われていた。

## 宿題

- 取り組んだレベル：**実装**
- やったこと：`app/ask.py` に `--chat` を追加した。`client.chats.create()` で作った1つのセッションに続けて `send_message()` し、`/exit` で終わる。1回だけ質問する通常モードはそのまま残し、両方のモードで入力・出力トークン数を表示する。API を呼ばずに動きを確かめる模擬テストを `tests/test_ask.py` に追加した。
- 結果：実際の Gemini で、前の回答を指す質問を続けて送った。
  - 1問目「LoRAとは何ですか？一文で答えてください。」→ 一文で回答（トークン 14 / 52）
  - 2問目「それを提案した論文の第一著者は誰ですか？名前だけ答えてください。」→ **「Edward J. Hu」**（トークン 84 / 4）
  - 対照として、同じ2問目を通常モード（履歴なし）で送ると「どの論文や提案について言及されているか分かりません」と返った（トークン 18 / 28）
  - 2問目の入力 84 トークンは、1問目の質問 14 ＋ 1問目の回答 52 ＋ 2問目の質問 18 の合計とちょうど一致した。前の質問と回答が毎回まとめて送られていることが数字で確かめられた。
  - `uv run pytest -q` は 12 passed。
- 使ったモデル：回答を生成したのは `gemini-3.5-flash-lite`。実装には OpenAI Codex（GPT-6 系）を、実 API での動作確認とこの answer.md の更新には Claude Code（Claude Opus 5.5）を使った。
- 気づき・疑問：
  - 会話履歴は SDK のチャットセッションが手元で持ち、毎回すべて送り直している。そのため、往復するたびに入力トークンが増える。長く話すほど1回あたりの入力が膨らむので、無料枠のトークン上限にも早く近づくはず。
  - 標準入力をパイプで渡したため、プロンプト「質問> 」の後ろに入力した文字が表示されず、ログの見た目は少し崩れた。対話として手で打つ分には問題ない。
